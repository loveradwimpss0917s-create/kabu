# Edge候補台帳 — 検証状況と次に何ができるか

外部レビュー資料（2026年8月）が挙げた105件のEdge候補を、**我々が実際に何を検証し、
何がまだできないのか**で分類した作業台帳。

## この台帳の目的

1. **同じ検証を繰り返さない。** 否定済みの仮説を別名で再検証しないための照合表
2. **「候補リスト」と「使える戦略」を混同しない。** 資料のStatus列は著者自身が
   「筆者の総合判断であり再検証が前提」「数値は過剰適合の誘惑を招くため意図的に
   提示していない」と明記している。**あれは検証すべき候補であって、使える戦略ではない**
3. **次の一手を、データ制約から逆算して決める**

## 検証を再開する際の必須ルール

過去2回、測定器自体の欠陥で誤った結論を出しかけた（誤検出率57%→14%、
さらに23%→較正後0%）。以下は必ず守る。

1. **事前登録**: 仮説・期待符号・判定基準を実行前にコードへ固定し、後から変えない
2. **全結果を報告**: 都合の良いものだけ選ばない
3. **信頼区間は1.5倍に較正**: ブロックブートストラップは銘柄横断方向の不確実性を
   取りこぼし標準誤差を約23%過小評価する（合成データで実測済み）
4. **日ごとの平均を使う**: 観測行ごとの平均は強気相場に重みが偏る
   （実際に+0.25%の見かけ上の優位性を生み、訂正した経緯がある）
5. **コスト差引後で判断**: 往復0.30%（手数料無料なら0.10%程度）
6. **多重検定を数える**: 既に10仮説を試した事実を試行回数に含める。
   候補が複数出た段階で **DSR（Deflated Sharpe Ratio）** を導入する

### DSR/PBOをまだ実装していない理由

これらは「有望なEdgeが複数見つかった後に本物を選別する」道具である。
現時点で選別すべき候補が1つもないため、道具を先に磨いても切るものがない。
C群・D群の検証が始まり候補が出た段階で、DSRから実装する
（既に10仮説を試した事実を試行回数として補正に織り込めるため、我々の状況に最も適合する）。
