## 0. 最重要発見（レビュー中に見つけた本番障害の根本原因）

**日次cronスキャンは、現在の構成では一度も成功できない。**

- `wrangler.toml:11` の cron (23:00 UTC) は `runScanner(env)` を **maxStocks指定なし** で呼ぶ（worker.js:586）。
- その場合 `SCAN_STOCKS` 全80銘柄をfetchする。サブリクエスト数 = crumb取得2 + N225 1 + 銘柄80 + Supabase DELETE/INSERT 2 = **約85**。
- Cloudflare Workers 無料プランの上限は **50サブリクエスト/実行**。約47銘柄目以降のfetchは "Too many subrequests" で例外→`scanStock`のcatchでnull化→さらに **Supabaseへの書き込みfetch自体も失敗**→cronは毎日失敗ログを吐いて終了。
- 手動スキャン（`/api/scan-trigger`）だけが44銘柄制限（worker.js:521）で49サブリクエストに収まり成功していた。
- **帰結**: 日次の自動書き込みが行われず、手動スキャンをしない期間が1週間続いた時点でSupabase無料プロジェクトが自動一時停止 → 前回の「530 error 1016」障害につながった。**表面のエラーではなく、この構造が真因。**

→ 修正はTOP10の第1位に記載（cron側も44銘柄に制限 or 複数回に分割）。

## 3. 株分析ロジックレビュー

> 詳細はV2設計書Mission 2/3で全指標を「残す/改善/削除」分類済み。ここでは差分要点のみ。

**不足している分析（重要順）**:
1. **流動性（売買代金）フィルタ** — 現在皆無。約定可能性はすべての前提。`volume×close` の20日平均で足切り。
2. **クロスセクション相対評価** — 全指標が単銘柄絶対評価。地合いが良い日は全銘柄高得点になり選別力を失う。同日全銘柄内の順位（percentile）で表現すべき。
3. **信用需給**（信用倍率・空売り残・逆日歩）— 日本株固有のエッジ源泉。データ調達が課題（P2）。
4. **決算サプライズ/PEAD** — 決算「前」の除外(#7)はあるが「後」のドリフト捕捉がない。
5. **β・対TOPIX相対リターン** — 個別の強さは市場を引いて初めて分かる。

**分析順序の提案（現状: 全指標を並列加点 → 提案: 漏斗型）**:
```
①ユニバース選定（流動性・値付き・市場）
→ ②レジーム判定（地合い: 順張り可否）
→ ③断面ランキング（モメンタム/52W高/低ボラ等の合成z）
→ ④個別確認（決算接近・ニュース・パターンは"拒否権"として使う）
→ ⑤執行計画（サイズ=リスク%÷ATR、損切り・利確を先に決める）
```
判断基準は「点数が高いから買い」ではなく「**上位◯%かつ拒否条件なし、かつRRが◯以上取れる形**」へ。

**バグ級の論理矛盾（即修正推奨）**: index.html:989 は決算7日以内に **+15点**、一方 #7 の実装は決算3日前を**除外**。同一アプリ内で「決算前は買い材料」と「決算前は危険」が併存している。V2方針（除外→通過後ドリフト捕捉）に統一すべき。

## 5. AIレビュー（AIがもっと賢くなるために）

現状「AI」と呼べる要素は加点ルールのみ。提案（効果×コスト順）:

1. **根拠付き要約カード（最優先・小さく始める）**: 分析結果JSON（スコア内訳・地合い・ニュース見出し）をClaude APIに渡し、「強気材料/弱気材料/最大リスク/無効化条件（このシナリオが崩れる価格）」を4行で生成。**必ず入力データへの参照を付け、データにない主張を禁止するプロンプト**にする。
2. **不確実性の明示**: スコアではなく「過去の同条件でのアウトパフォーム率（V2のsignal_tracking由来）±信頼区間」を表示。AIらしさより誠実さが差別化になる。
3. **ニュースの構造化**: 見出し8本を「材料の種類（決算/提携/レーティング/不祥事…）・方向・重要度」にタグ付けさせ、スコアの"拒否権"に接続。
4. **エージェント化は段階的に**: いきなりマルチエージェントではなく、(a)日次ブリーフ生成 → (b)「なぜ上がった?」の事後説明 → (c)仮説提案（V2の検証基盤に投げるSQL/条件を生成）の順。**検証基盤(V2 P0)がないとAIの提案は検証不能な作文にとどまる。**
5. **RAG**: 過去の自分の取引ジャーナル＋過去スキャン結果を検索対象にし「似た局面の過去成績」を提示。外部文書RAGより先に自前データRAG。
6. **自己評価ループ**: AI要約に「予測」を含めた場合は必ずsignal_trackingに記録し、的中率をAI自身のプロンプトにフィードバック。

## 8. Sonnet向け実装仕様（優先度「高」の各項目）

### 仕様A: cronスキャン修正（B1+B2+B3）
- **目的**: 日次スキャンを実際に成功させ、Supabase自動停止の再発を防ぐ。
- **実装内容**:
  1. worker.js `scheduled()` を `runScanner(env, 44)` に変更（手動と同一の44上限）。
  2. `runScanner` のSupabase書き込みを DELETE+INSERT から UPSERT 1回に変更: `POST /rest/v1/scan_results` に `Prefer: resolution=merge-duplicates`。
  3. 事前にSupabaseで `alter table scan_results add constraint scan_results_pk primary key (code, scan_date);`（既存PKがあれば置換。重複行は先に除去）。
  4. 日付関数 `jstDateStr()` を新設: `new Date(Date.now()+9*3600*1000).toISOString().slice(0,10)` を worker内の`today`に使用。
  5. INSERT失敗時のthrowメッセージに「Supabase無料プランが一時停止している可能性があります。ダッシュボードでRestoreしてください」を含める。
- **API/データモデル変更**: PK追加のみ。レスポンス互換。
- **テスト項目**: (1) `wrangler dev` で `curl -X POST /api/scan-trigger` → ok:true, saved>0。(2) 同日2回実行して行数が増えない（UPSERT確認）。(3) 保存された scan_date がJST今日。
- **完了条件**: Cloudflareダッシュボードのcronログで「Cron scanner完了」が出ること。

### 仕様B: スコア計算のworker一本化（B4）
- **目的**: スキャナーと詳細画面のスコア不一致を根絶し、ロジック修正を1箇所にする。
- **実装内容**:
  1. 新エンドポイント `GET /api/analyze/:code?interval=1d` を worker に追加。処理: chart取得→有効足抽出→`calcTradeScore`(worker版に「材料/アナリスト」項目を統合した完全版)→`{score, signal, details[], indicators{rsi,atrPct,...}, ohlcv{dates,o,h,l,c,v}(描画用), summary(quoteSummary要約)}` を返す。
  2. index.html `analyze()` は `/api/analyze/:code` を1回fetchし、返却JSONで描画のみ行う。フロントの`calcTradeScore`と重複指標関数は削除（チャート描画用の軽量計算のみ残す）。
  3. details[] の各要素は `{name, pts, d, icon}`（現行フロント形式）で互換維持。
- **UI変更点**: なし（表示互換）。
- **エラーハンドリング**: workerで銘柄不明時 `404 {error:'銘柄コードが見つかりません'}`。フロントは既存 `showErr` に表示。
- **テスト項目**: 同一銘柄でスキャナー行のスコアと詳細画面のスコアが一致。既存の全タブ描画が回帰しない。
- **完了条件**: `grep -c "function calcTradeScore" index.html` が0。

### 仕様C: 決算矛盾解消（B5）
- **実装内容**: index.html:987-991 の決算加点ブロックを削除し、代わりに `daysEar in [0,3]` なら `add('決算接近', -100適用ではなく) → スコアとは別に `excluded:true, excludeReason:'決算'+daysEar+'日前'` を返す（#7と同一挙動に統一）。8-30日は表示のみ（±0点）。
- **完了条件**: 決算7日前銘柄のスコアが決算によって上がらないこと。

### 仕様D: Yahooプロキシキャッシュ
- **実装内容**: worker.js `handleYfin` 冒頭で `caches.default.match(cacheKey)`（cacheKeyは `_t`除去済みURL）。ヒットで即返却。ミス時fetch後、200のみ `Cache-Control: s-maxage=180` を付けて `cache.put`。フロントの `_t=Date.now()` を全廃。
- **テスト項目**: 同一銘柄2回目の分析が体感即時。Cloudflareログでサブリクエスト減。
- **完了条件**: 3分以内の同一リクエストがYahooへ到達しない。

### 仕様E: 調整済み終値
- **実装内容**: chart応答の `indicators.adjclose[0].adjclose` を取得し、**指標計算はadjclose、表示価格はclose** と分離。adjclose欠損時はcloseにフォールバックし `adjusted:false` フラグを返す。
- **テスト項目**: 直近に分割があった銘柄（例: 直近1年で分割実施銘柄）でEMA200が急段差にならない。
- **完了条件**: スコア計算入力がadjcloseであること（コードレビューで確認）。

### 仕様F: セキュリティ最小セット
- **実装内容**:
  1. `/api/scan-trigger`: `env.SCAN_TOKEN`（wrangler secret）と `Authorization: Bearer` 照合。フロントは同トークンを持たない→UIの手動スキャンボタンは「1日1回まで」のworker側レート制限（KVで当日カウント）に置換 or トークン埋め込みを許容するなら簡易でも可（個人利用前提）。
  2. `handleYfin` にパス許可リスト: `/v8/finance/chart/`, `/v10/finance/quoteSummary/`, `/v1/finance/search` 以外は403。
  3. index.htmlに `function esc(s){return String(s).replace(/[&<>"']/g,c=>({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[c]))}` を追加し、ニュース・銘柄名等の外部文字列挿入箇所（renderNews, renderScannerList等）を全て `esc()` 経由に。
- **テスト項目**: 許可外パス `/yfin/v6/finance/quote` が403。`<img onerror>` を含む偽RSSタイトルが無害化。
- **完了条件**: 上記2テストの通過。
